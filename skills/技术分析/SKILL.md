# 技术形态分析 Skill v0.0.8-basic

## 版本定位

本 skill 面向中国金融市场的基础技术形态分析，核心入口是 `scripts/analyze_universal.py`。

它会完成以下工作：

1. 获取标的日线行情数据。
2. 识别 TA-Lib 61 种经典 K 线形态。
3. 计算核心技术指标与扩展指标。
4. 扫描非核心指标的极端分位和同类共振。
5. 统计近 3 日形态在过去约 3 年窗口内的历史胜率、盈亏比和 5 日期望。
6. 输出 Markdown 报告、主图和必要的形态详图。

本版本是基础版，不输出高级价格形态结论，例如波段结构、W底/M顶、头肩形态、三角形/楔形/旗形、缺口分析、严格 RSI 背离识别。若用户要求这些高级形态，应说明当前基础版不支持，避免自行补充不存在的代码能力。

## 角色与表达原则

执行本 skill 时，以“多资产技术分析专员”的口径工作：

- 使用中文金融术语，例如金叉/死叉、多头排列/空头排列、布林带开口/收口、超买/超卖、量价配合。
- 报告解读以“状态描述”和“多维交叉验证”为主，不把技术信号表述成确定性预测。
- 涉及国债期货时，提醒债券品种波动率低，指标阈值和权益资产不可机械类比。
- 始终提示：技术分析仅用于辅助判断，不构成投资建议。

### 颜色约定

本 skill 遵循中国市场惯例：

- 红色 / 🔴 = 上涨、看涨、阳线、多头。
- 绿色 / 🟢 = 下跌、看跌、阴线、空头。

图表、报告和口头解读都必须遵守此约定，避免套用欧美市场“绿涨红跌”的习惯。

## 执行工作流

### 1. 确认标的

优先根据用户表述映射标的代码。常见预设如下：

| 用户表述 | 标的代码 | 代码内配置 |
|---|---:|---|
| 十年国债期货、T主力、T0 | `T0` | 预设 |
| 五年国债期货、TF主力、TF0 | `TF0` | 预设 |
| 二年国债期货、TS主力、TS0 | `TS0` | 预设 |
| 上证指数、上证综指、大盘 | `sh000001` | 预设 |
| 深证成指 | `sz399001` | 预设 |
| 深证 AI 产业指数 | `sz399639` | 预设 |
| 沪深300 | `sh000300` | 预设 |
| 平安银行 | `000001` | 预设 |
| 贵州茅台、茅台 | `600519` | 预设 |
| 其他 A 股代码 | 代码本身 | 动态创建 |

如果用户没有指定标的，默认分析 `T0`。

### 2. 运行主脚本

主入口：

```bash
python scripts/analyze_universal.py -s {标的代码} [-d {图表天数}] [-l {分位数窗口}] [-o {输出目录}] [--no-chart]
```

参数说明：

| 参数 | 含义 | 代码默认值 |
|---|---|---:|
| `-s`, `--symbol` | 标的代码 | `T0` |
| `-c`, `--config` | 指定预设配置名 | 无 |
| `-d`, `--days` | 主图展示交易日数量 | `120` |
| `-l`, `--lookback` | 指标分位数回看窗口 | `756` |
| `-o`, `--output` | 输出目录 | `../技术形态分析` |
| `--no-chart` | 只生成报告，不生成图表 | 默认生成图表 |

示例：

```bash
python scripts/analyze_universal.py -s T0
python scripts/analyze_universal.py -s sh000001 -d 60
python scripts/analyze_universal.py -s 600519 -o ./output
python scripts/analyze_universal.py -s T0 --no-chart
```

注意：如果当前环境没有 `python` 命令，需先确认 Python 解释器路径或激活对应环境。

### 3. 读取输出

脚本会输出：

1. Markdown 报告：`{代码}_技术分析报告_{日期}.md`
2. 主图：`{代码}_TA_{日期}.png`
3. 形态详图：`{代码}_PATTERN_{形态代码}_{形态日期}.png`

形态详图只在近 3 日识别到可展示形态时生成。

### 4. 向用户汇报

不要直接整篇复制报告。先读取 Markdown 报告，再按“五维内部一致性 + 跨维度交叉验证”的框架重组表达。

核心逻辑：

```text
趋势和动量决定方向，量价决定可信度，波动和位置风险决定风险，K 线形态用于辅助确认或削弱信号。
```

汇报时按三层完成判断：

1. **维度内部一致性验证**：先判断每个维度内部的信号是否同向，避免孤立罗列指标。
2. **跨维度交叉验证**：再看方向、质量、风险三类确认关系。
3. **结构化表达**：最终输出“技术状态判断 -> 信号确认度 -> 风险提示”。

#### 4.1 五维状态定义

五维不是全部强行输出“偏多/偏空”。每个维度有自己的语义：

| 维度 | 回答的问题 | 核心状态 | 核心证据 |
|---|---|---|---|
| 趋势 | 方向结构是否成立 | 偏多 / 偏空 / 中性 / 分歧 | 价格相对 MA、均线排列、MACD DIF/DEA 结构、关键位 |
| 动量 | 边际强弱是否修复或转弱 | 修复 / 转弱 / 过热 / 偏弱 / 分歧 | RSI、KDJ、CCI、WILLR、MACD 柱体变化 |
| 波动 | 市场环境是扩张还是收敛 | 扩张 / 收敛 / 常态 / 高波动 / 低波压缩 | ATR、ATR 分位、BOLL Width、BOLL 位置 |
| 量价 | 价格变化是否有成交和资金流配合 | 配合 / 不配合 / 背离 / 中性 | 成交量、量比、OBV、AD、ADOSC |
| 位置风险 | 信号是否过热、过冷、拥挤或异常 | 过热 / 过冷 / 异常共振 / 低波压缩 / 无明显极端 | 历史分位、非核心指标异常、同类指标共振 |

重要分工：

- **MACD 不重复计分**：趋势维度使用 DIF/DEA 结构、金叉/死叉、零轴上方/下方；动量维度只使用 MACD 柱体扩张/收缩等边际变化。
- **MFI 不作为两个维度的核心指标**：动量核心优先用 RSI、KDJ、CCI、WILLR；量价核心优先用成交量、量比、OBV、AD、ADOSC。MFI 可作为补充或异常扫描证据，不在动量和量价中重复作为核心依据。
- **波动不直接判断多空**：ATR 上升、BOLL Width 扩大只说明波动扩张，不直接等于看多或看空；必须和趋势、动量结合判断方向。
- **位置风险是风险过滤层**：极端高低分位不直接给方向结论，而是提示过热、过冷、低波压缩、拥挤或异常共振。

#### 4.2 维度内部一致性验证

每个维度先输出三项：

```text
维度状态：例如“趋势中性偏弱”
一致性：高 / 中 / 低
依据：2-4 个关键证据
```

判断规则示例：

- 趋势：价格、均线排列、MACD DIF/DEA 若同向，则一致性高；若价格仍在支撑上方但 MACD 死叉，则一致性中等或偏低。
- 动量：RSI、KDJ、CCI、WILLR、MACD 柱体若同步修复或转弱，则一致性高；若短周期走弱但中周期仍中性，则标记分歧。
- 波动：ATR 分位、BOLL Width、BOLL 位置共同指向收敛或扩张时，一致性高；若 ATR 低但价格贴近 BOLL 上/下轨，则说明压缩中有方向试探。
- 量价：量比、成交量、OBV、AD、ADOSC 同向支持价格变化时为配合；价格变化但量能和资金流不支持时为不配合或背离。
- 位置风险：多个同类指标同时处于极端分位时为异常共振；单个指标极端时提示局部风险，不放大为整体方向判断。

#### 4.3 跨维度交叉验证

把跨维度验证压缩为三类结论：

| 验证类型 | 主要组合 | 作用 |
|---|---|---|
| 方向确认 | 趋势 x 动量 | 判断方向信号是否可信 |
| 质量确认 | 趋势 x 量价 | 判断突破、反弹或下跌是否有成交和资金流配合 |
| 风险确认 | 动量 x 波动 x 位置风险 | 判断是否存在过热、过冷、低波压缩、拥挤或回撤风险 |

K 线形态作为辅助验证层：

- 形态与趋势、动量、量价同向时，提高信号确认度。
- 形态与指标方向相反时，提示分歧。
- 形态历史胜率、盈亏比、5 日期望只能作为历史统计证据；样本量不足时必须降权。

#### 4.4 建议汇报模板

先读取报告中的“核心观点与交易提示”“技术面信号总览”“核心技术指标”“K 线形态识别”“辅助信号与异常提示”“后市情景推演”和附录，再按以下模板输出：

```text
【分析标的】标的名称（代码）
【最新收盘】价格、日期、涨跌幅

【技术状态判断】
一句话概括当前状态，例如：震荡整理 / 趋势修复 / 趋势转弱 / 高位钝化 / 低位修复 / 波动压缩待突破。
说明该判断来自哪些维度的共同结果。

【五维状态】
趋势：状态 + 一致性 + 关键证据。
动量：状态 + 一致性 + 关键证据。
波动：状态 + 一致性 + 关键证据；只描述环境，不直接判断多空。
量价：状态 + 一致性 + 关键证据。
位置风险：状态 + 一致性 + 关键证据；提示过热、过冷、低波压缩或异常共振。

【交叉验证】
方向确认：趋势 x 动量是否相互验证。
质量确认：趋势 x 量价是否相互验证。
风险确认：动量 x 波动 x 位置风险是否提示追涨、杀跌、低波压缩或拥挤风险。
形态验证：最近 K 线形态是增强还是削弱上述判断。

【信号确认度】
高 / 中 / 低。说明确认度来自哪些维度一致，哪些维度分歧。

【关键点位与情景】
列出上方阻力、下方支撑，以及突破/跌破时对应的状态切换。

【风险提示】
说明量能不足、极端分位、形态样本量不足、低波压缩、债券低波动特征等限制。

【文件】
报告路径、主图路径、形态详图路径。
```

解读要求：

- 先讲维度内部一致性，再讲跨维度验证，最后给技术状态和风险提示。
- 对异常指标要说明其功能，尤其是 CCI、MFI、ADX、AD振荡器、终极振荡器、APO、PPO 等不常见指标。
- 历史胜率、盈亏比、5 日期望只能表述为历史统计规律，不代表未来。
- 不要给出确定性买卖建议；可以说“关注某点位是否确认”“若突破/跌破则对应情景切换”。

## 代码能力清单

### K 线形态

`scripts/analyze_universal.py` 内置 TA-Lib 61 种经典 K 线形态，包含单 K、双 K、多 K 组合形态，例如十字星、锤子线、上吊线、吞没形态、孕线、乌云盖顶、刺透形态、早晨之星、黄昏之星、三只乌鸦、三白兵等。

### 核心指标

报告正文直接展示或使用的核心指标包括：

- MA5、MA10、MA20、MA60
- MACD、Signal、柱体
- RSI(6)、RSI(12)
- KDJ: K、D、J
- BOLL 上轨、中轨、下轨
- ATR(14)
- 量比
- OBV / AD 相关量价状态

### 扩展指标库

`scripts/indicators_lib.py` 还计算更多指标，用于异常扫描、问答和扩展：

- 趋势类：SMA、EMA、DEMA、TEMA、KAMA、T3、TRIMA、WMA、SAR、HT_TRENDLINE
- 动量类：RSI、MACD 系列、KDJ、STOCH、WILLR、CCI、MOM、ROC、TRIX、ULTOSC、CMO、APO、PPO、BOP
- 波动率类：ATR、NATR、TRANGE、STDDEV、VAR、BOLL %B、BOLL Width、AVGDEV
- 成交量类：OBV、AD、ADOSC、MFI
- 趋势强度类：ADX、ADXR、DX、+DI、-DI、+DM、-DM、AROON、AROONOSC

### 信号扫描

`scripts/signal_scanner.py` 提供：

- 非核心指标极端分位扫描。
- 高优先级阈值：>=95% 或 <=5% 分位。
- 中优先级阈值：>=90% 或 <=10% 分位。
- 同类指标共振检测。
- K 线形态与指标的交叉验证和分歧检测。

### 指标问答扩展

`scripts/indicator_query.py` 支持：

- 查询单个指标值和分位数。
- 查询某类指标概况。
- 根据自然语言问题匹配波动、趋势、动量、成交量、综合对比等指标组。
- 对比两个标的的多个指标。

如果用户只问某个指标或要求两个品种对比，可优先考虑读取并使用该模块，而不是重新跑完整报告。

## 数据源

当前代码实际实现的数据源顺序为：

1. AKShare 主接口
2. Tushare，需要配置 `TUSHARE_TOKEN` 或 `~/.tushare_token`
3. BaoStock

当前代码没有实现腾讯财经 API 和新浪财经 API fallback。不要在汇报中声称脚本实际会自动调用这两个数据源。

## 数据源失败处理

如果脚本提示“所有数据源失败”，按顺序排查：

1. 当前环境是否能访问国内财经数据接口。
2. 是否安装依赖：`akshare`、`tushare`、`baostock`、`numpy`、`pandas`、`matplotlib`、`TA-Lib`、`scipy`。
3. Python 命令是否可用，必要时激活项目环境。
4. 标的代码是否正确，例如 `T0` 不是 `t0`。
5. 换一个预设标的测试，判断是单一接口问题还是全局环境问题。

## 使用边界

1. 技术分析仅用于辅助判断，不构成投资建议。
2. 单一 K 线形态或单一指标不能独立作为交易依据。
3. 基础版不输出高级形态识别结论。
4. 对历史胜率和期望值必须强调样本量、窗口和统计局限。
5. 数据来自外部财经接口，可能受网络、接口变更、交易日更新延迟影响。
