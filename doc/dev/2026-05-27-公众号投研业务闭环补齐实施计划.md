# 公众号投研业务闭环补齐实施计划

**Goal:** 在当前 `business/investment` 已有实现上，补齐 `doc/公众号智能辅助系统需求文档.raw.md` 中要求的缓存、导出、角色权限、长期记录、健康检查、真实公众号验收和上线可运维能力。

**Architecture:** 不重写现有 CowAgent 通道、Agent、Skill、Web 控制台；继续以 `business/investment` 作为投研业务服务层。公众号入口只做消息适配，Web API 只做鉴权、参数解析和响应渲染，核心业务逻辑沉到投资业务模块，新增缓存、导出、权限和审计服务以便后续策略模块复用。

**Tech Stack:** Python 3.12, web.py, SQLAlchemy Core, Alembic, PostgreSQL, Playwright, signal-card-renderer, ta-pattern Skill, pytest, mypy, ruff, node syntax check.

---

## 1. 当前基线

当前已经具备：

- 公众号投研路由入口：`channel/wechatmp/wechatmp_channel.py` 调用 `business.investment.router.handle_text_message`。
- Web 调试入口：`channel/web/web_channel.py` 中 `_build_investment_web_reply()` 支持 `利率`、`转债`、`xxx 技术分析`。
- 用户/白名单：`business/investment/user_service.py` 支持新增、更新、停用、Excel 增量导入、权限校验。
- 技术分析链路：`business/investment/technical_analysis.py` 已封装股票解析、TA Skill、AI 文本整理、卡片渲染。
- 利率/转债内容：`business/investment/daily_content.py` 已支持草稿、生成、重新生成、设为生效、查询最新生效内容。
- 记录：`business/investment/records.py` 已记录公众号请求、后台内容和输出文件。
- 后台：`channel/web/static/js/console.js` 已有用户、利率、转债、记录、配置、健康检查页面。
- 健康检查：`business/investment/health.py` 已检查数据库、目录、Skill/renderer 路径、模板、股票字典、模型、Playwright。

当前主要缺口：

- 技术分析结果缓存和 `cache_hit`。
- 服务记录字段不满足 raw 文档要求。
- 月度/季度 Excel 导出。
- 后台账号角色与 API 分权。
- 利率/转债“生效日期、多版本、替换记录、上传人员可见范围”不完整。
- 健康检查未覆盖全部运行依赖、中文字体、公众号配置和真实样例。
- 公众号真实异步体验未达到“一开始返回收到，稍后返回图”的业务预期。
- 真实外部 AI、公众号收发图、最终 e2e 仍需环境配置后复验。

## 4. 问题清单与建议方案

| 问题 | 影响 | 建议方案 |
| --- | --- | --- |
| 客户身份用 OpenID 还是手机号 | 公众号消息天然只有 OpenID，手机号不能强校验 | 首版强身份使用公众号 OpenID；手机号、姓名、机构只做白名单展示和导出字段。后续如必须用手机号，增加绑定流程。 |
| 技术分析是否返回“技术指标表”第三张图 | raw 文档提到信号卡、主图、技术指标表；当前二次开发文档和代码只返回两张图 | 首版继续返回两张图，指标表留后台；若业务坚持，新增 `indicator_table` artifact 并作为第三张图片返回。 |
| 技术分析标准文本用规则还是大模型 | 纯大模型稳定性和成本不可控；纯规则可能覆盖不足 | 短期保留现有 AI 整理，但加入字段校验和原文留档；中期推动 TA Skill 输出结构化 JSON，规则优先、AI 只补充摘要表达。 |
| 技术分析缓存行情日期怎么确定 | 缓存键必须依赖行情日期，否则同日/跨日容易混 | 优先从标准文本/Markdown 中提取 `行情日期`；提取失败用报告文件名日期；仍失败时用当前日期并记录 warning。 |
| 程序版本、模板版本如何定义 | 版本不清会导致缓存失效不可控 | 用文件 sha256：TA 脚本、renderer 脚本、模板 HTML、prompt 文本分别计算版本指纹，组成缓存版本。 |
| 利率是否直接上传最终 PNG 还是 AI 渲染 | raw 文档倾向利率直接上传 PNG，当前实现支持 AI+renderer | 两种模式都支持：利率默认允许“最终 PNG 直发”；转债默认 AI+renderer，因为段子必须进入最终图。 |
| 转债段子如何进入最终图 | 只上传信号 PNG 无法保证段子展示 | 后台保存原图和段子，AI/OCR 抽取信号图文本，再合并段子生成可转债标准文本；最终图必须人工预览后设为生效。 |
| 后台角色要不要完整账号体系 | 当前 `web_password` 不能区分上传人员和管理员 | 增加投资后台账号表和角色权限；保留 `web_password` 作为首次初始化/内网应急入口。 |
| 生产数据库用 SQLite 还是 PostgreSQL | 当前代码和迁移已偏向 PostgreSQL，文档部分仍写 SQLite | 生产明确使用 PostgreSQL；开发用 Docker PG；修正文档，避免运行时和部署文档冲突。 |
| 月度/季度导出用 CSV 还是 Excel | raw 文档要求 Excel | 使用 `openpyxl` 生成 `.xlsx`，加入运行依赖；CSV 可作为后续轻量备用，不作为验收主路径。 |
| 公众号长耗时技术分析如何回复 | 微信被动回复有超时限制，TA 链路可能超过 15 秒 | 推荐启用客服消息/主动发送：先被动回复“收到，正在运行”，后台生成后主动发图；若不具备主动发送权限，保留“回复任意文字获取结果”的降级体验。 |
| 是否保留通用 Agent 对客户开放 | 开放式问答会产生不可控投研回复 | 公众号客户默认不进入通用 Agent；只在后台配置 `router.enable_agent_fallback=true` 时允许未命中文本转 Agent，建议仅内测开启。 |
| 数据源优先级 | AKShare 免费但稳定性受网络影响；Tushare 需要 token；BaoStock 可补充 | 股票字典用 AKShare 主刷新，Tushare token 配置后补强；TA Skill 内部数据源按现有实现，健康检查做真实样例验证。 |
| 健康检查是否每次都跑真实 TA | 真实 TA 和渲染耗时，不适合每次打开页面自动跑 | 默认做轻量检查；按钮触发完整 smoke，包括测试标的 TA 和三类 renderer 样例。 |
| 业务记录保存多久 | raw 文档要求长期保存，图片文件会占空间 | 请求记录长期保存；可再生成缓存文件按 6 个月清理；客户可见输出和审计产物按 12 个月保留，清理策略必须只删文件不删记录。 |
| API Key 和客户信息安全 | 前端、日志、导出都可能泄漏敏感信息 | API Key 全程脱敏；服务记录导出默认包含客户业务字段但不含密钥；日志 detail 统一过 `sanitize_sensitive_text()`。 |
| 是否需要自动告警 | raw 文档强调稳定性，但当前只有后台查看 | 上线首版先在健康检查和记录页展示；试运行后增加阈值告警，例如连续 3 次模型/数据源/渲染失败通知技术管理员。 |

## 6. 验收标准

完成后必须满足：

- 白名单客户输入 `300502.SZ 技术分析` 可收到处理提示，并最终收到信号卡 PNG 和主图。
- 同标的、同行情日期、同版本第二次技术分析命中缓存。
- 白名单客户输入 `利率` 可收到最新已生效利率 PNG。
- 白名单客户输入 `转债` 可收到包含段子的最新已生效转债 PNG。
- 未授权、停用、过期、输入错误、股票不存在、名称歧义、数据源失败、渲染失败均返回业务提示。
- 后台可新增/编辑/停用/导入/导出白名单。
- 后台可上传、生成、预览、替换、设为生效每日内容，并查看操作流水。
- 后台可按时间范围、月度、季度导出服务记录 Excel。
- 后台角色分权生效，上传人员不能修改白名单、缓存和系统配置。
- 健康检查能区分 `ok`、`warning`、`error`，并能运行完整 smoke。
- API Key 不在前端、日志、导出文件、错误响应中明文出现。
- `py -m pytest`、`py -m mypy business tests`、`py -m ruff check .`、`node --check channel/web/static/js/console.js` 全部通过。
