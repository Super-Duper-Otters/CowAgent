# 投研后台运营工作台改造设计

## 目标

先修正当前 Web 后台不适合运营使用的问题，把投资业务后台改成可扫读、可确认当前生效图、可稳定执行上传/生成/生效操作的运营工作台。

本轮先做页面和薄 API 契约，不做完整角色权限、缓存、Excel 导出和审核流。

## 范围

### 业务记录

- 页面顶部增加“刷新记录”按钮。
- 公众号请求记录和后台生成记录默认用紧凑表格展示。
- 长字段不直接撑高行：
  - 失败原因只显示一行摘要。
  - 输出文件显示文件数量和文件名摘要。
  - 原始输入限制宽度。
- 每行增加“详情”按钮，打开页面内详情面板，展示完整失败原因、用户提示、输出文件链接、原始输入和时间。

### 利率内容

- 页面改为三块：
  - 当前生效利率图：置顶展示大预览、状态、生效时间、操作人、文件链接。
  - 上传/生成：保留资料文本、资料文件、操作人、保存草稿、保存并生成。
  - 历史记录：紧凑展示历史内容，支持刷新、生成、设为生效、详情。
- 当前生效图由后端接口直接返回 `current_effective`，前端不从列表猜。

### 转债内容

- 页面结构与利率一致。
- 上传区明确分为资料文本、段子/补充文本、资料文件。
- 当前生效转债图置顶展示，确保运营知道公众号客户当前会收到哪张图。

### 系统配置

- 配置页按运营优先级分组：
  - 股票字典与数据源。
  - 技术分析与渲染。
  - 存储与提示词。
- prompt 长文本默认在独立分组内展示，不与短字段挤在同一个密集网格。
- 保留股票字典维护工具。

## API 契约调整

`GET /api/investment/daily-content?service_type=rate` 返回：

```json
{
  "status": "success",
  "current_effective": {
    "content_id": "...",
    "service_type": "rate",
    "status": "effective",
    "output_image": "C:/...",
    "operator": "admin",
    "effective_at": "...",
    "created_at": "..."
  },
  "contents": []
}
```

没有生效内容时，`current_effective` 为 `null`。

## 验收

- 利率/转债页第一屏能看到当前客户会收到的图片。
- 业务记录页有刷新按钮。
- 失败原因和输出文件不会撑高整行。
- 每条记录可打开详情查看完整内容。
- `node --check channel/web/static/js/console.js` 通过。
- 投资业务相关 Python 测试通过。
